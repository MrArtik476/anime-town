# Этап 6d — загрузка субтитров и сводка по сайту (дизайн)

Дата: 2026-11-14. ADR-030.

## Зачем

Сейчас администратор вписывает адрес готового `.vtt`, лежащего где-то в интернете. Нужно загружать файл субтитров
с компьютера прямо в форме серии и хранить его у себя. На главной админки нужна сводка: что происходит на сайте.

Своего видео с правами нет — до этапа 8 работаем на открытых тестовых потоках (ADR-022). Поэтому видео остаётся
по ссылке, как сейчас; загрузка видео отложена до выбора видеохостинга на этапе 8 (записать в ADR-030).

## Цели

1. Загрузка `.vtt` с компьютера в Supabase Storage из формы субтитров `/admin/episodes/[animeId]`.
   Ввод адреса вручную остаётся (внешний `https://…`, тестовые `/media/test/…`).
2. Бакет закрытый: файл черновика (`license_status = 'none'`) и скрытого тайтла (`anime_hidden`) не открывается
   ни по ссылке сайта, ни запросом напрямую в Storage.
3. Сводка на `/admin`: пользователи (всего, новые за 7 дней), серии (опубликованные, черновики), скрытые тайтлы,
   открытые жалобы, активные баны, комментарии за 7 дней.

## Не цели

- Загрузка видео (этап 8). Перекодирование, ffmpeg.
- Перенос уже существующих внешних субтитров в Storage.
- Графики и история сводки — только текущие числа.

## Анти-цели (провал, даже если «работает»)

- Файл черновика или скрытого тайтла скачивается кем-то, кроме администратора.
- Проверка прав только в коде приложения (служебный ключ читает всё, а код решает, кому отдать).
- Удалённые или заменённые субтитры оставляют «сирот» в бакете.

## Подход (выбран вариант А)

| Вариант | Суть | Почему не он |
|---|---|---|
| **А. Сайт отдаёт файл после проверки** | Закрытый бакет `subtitles`; адрес субтитров — `/media/subtitles/<uuid>.vtt`; обработчик маршрута читает файл из Storage от имени смотрящего | — выбран |
| Б. Временные ссылки (signed URL) | Сервер выдаёт ссылку на час | Работает после скрытия тайтла до истечения; страница серии кэшируется — в кэше просроченные ссылки |
| В. Браузер качает файл сам и подставляет плееру | `fetch` со входом → blob → `<track>` | Новая логика в плеере, не работает без скриптов; защищает так же, как А |

Уточнение к А (моё решение, сверено с пользователем в разговоре): обработчик читает файл **не служебным ключом**,
а клиентом смотрящего (сессия из cookies или гость). Чтение `storage.objects` разрешает политика, которая
проверяет, что строка `subtitles` с этим адресом видна читающему — а её видимость уже определяют RLS `subtitles`
и `episodes` (черновики, скрытые тайтлы, ADR-029). Права целиком в базе; прямой запрос в Storage в обход сайта
получает тот же отказ; E2E работает без служебного ключа.

## Как закрыты файлы

| Кто | Загрузить / удалить | Читать из Storage (API) | `/media/subtitles/…` |
|---|---|---|---|
| Гость | нет | только если серия опубликована и тайтл не скрыт | так же |
| Пользователь, модератор | нет | так же | так же |
| Администратор | да (своя сессия, политика `private.is_admin()`) | все | все |

- Бакет `subtitles`: `public = false`, лимит 512 КБ, MIME `text/vtt` (и `text/plain` — браузеры по-разному
  определяют `.vtt`; сервер всё равно проверяет содержимое).
- Сервер (Server Action) до загрузки проверяет: размер ≤ 512 КБ, файл начинается с `WEBVTT` (после BOM),
  UTF-8. Имя — `crypto.randomUUID() + ".vtt"`, папок нет: адрес не угадать и он не раскрывает серию.
- Политика чтения: `bucket_id = 'subtitles' and exists (select 1 from public.subtitles s where s.url = '/media/subtitles/' || name)`
  для `anon, authenticated`. Вложенный запрос идёт с RLS читающего.
  Администратор читает все файлы бакета (отдельная политика `(select private.is_admin())`): удаление в Storage
  требует и права чтения, а файл удаляется уже после удаления строки, когда первая политика его не пропускает.
- Запись: insert / delete — только `authenticated` с `(select private.is_admin())`; update не нужен (имя всегда новое).
- Ответ обработчика: `Content-Type: text/vtt; charset=utf-8`, `Cache-Control: private, no-store`,
  `X-Content-Type-Options: nosniff`. Нет строки или файла — 404 (без различия «нет» и «нельзя»).
- Адрес `/media/subtitles/<uuid>.vtt` проходит существующее check-ограничение `subtitles.url`
  (`^(https://|/media/)…\.vtt`) — миграция без `DROP`, код плеера не меняется.

## Жизненный цикл файла

1. В форме субтитров — выбор «Файл с компьютера» (по умолчанию) или «Адрес». Файл уходит вместе с формой
   (`FormData`) в одно действие «Сохранить субтитры» (`saveSubtitle`): проверка → загрузка в бакет → вставка или
   изменение строки. Строка не сохранилась — загруженный файл сразу удаляется. Отдельной «загрузки заранее» нет,
   поэтому нет и непривязанных файлов, которые кто-то должен читать.
2. При изменении строки с новым файлом (или переходе на внешний адрес) прежний файл бакета удаляется после
   успешного сохранения.
3. Удаление субтитров (`deleteSubtitle`) и серии (`deleteEpisode`, каскад) — файлы бакета этих строк удаляются
   после удаления строк (адреса читаются до удаления).
4. Если удаление файла не удалось (сбой сети) — строка уже сохранена/удалена, ошибка пишется в лог, файл
   остаётся «сиротой»: прочитать его никто, кроме администратора, не может (нет строки — политика чтения
   не пропускает). Известное ограничение, записать в ADR-030.
5. Лимит тела Server Action в Next.js — 1 МБ по умолчанию: 512 КБ файла проходят без настройки.

## Сводка на `/admin`

Запросы `count` (`head: true`) от имени администратора, без служебного ключа и без новой функции в базе:
`profiles` (всего; `created_at >= now - 7 дней`), `episodes` (по `license_status`), `anime_hidden`,
`comment_reports` (`status = 'open'`), `user_bans` (не снят и не истёк), `comments` (за 7 дней).
Число не загрузилось — в карточке «—» и общее сообщение об ошибке. Карточки разделов остаются; сводка — сверху,
сетка чисел (на 360 px — 2 колонки).

## Ограничения

- Supabase Storage Free — 1 ГБ на всё; субтитры — килобайты, проблемы нет.
- Внешние адреса субтитров (`https://…`) по-прежнему открыты всем — это чужие файлы.
- Время «7 дней» читается после `requireAdmin()` (ошибки 12/34).

## Проверка

- unit: проверка файла (`WEBVTT`, BOM, размер, пустой), разбор имени из адреса, модель сводки.
- E2E (мок): загрузка `.vtt` → субтитры видны в плеере; гость получает 404 на файл черновика и скрытого тайтла;
  удаление субтитров удаляет файл; сводка показывает числа. Мок повторяет политики бакета.
- `npm run rls:check`: блок «Субтитры в Storage» на настоящей базе.
